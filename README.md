# ProveBench

**How fast is ZK proving, really? On a laptop, in a browser, and on your phone.**

ProveBench runs the *same statements* with the *same inputs* through different proving systems and reports what it actually costs: witness generation, proving, verification, proof size and peak memory. A static web page runs the browser suite on whatever device opens it and ranks it against reference runs.

| System | Prover (native) | Prover (browser) | Arithmetization |
|---|---|---|---|
| Noir `1.0.0-beta.19` | `bb` 4.0.0-nightly.20260120 (UltraHonk) | `@aztec/bb.js` same version | UltraHonk gates (PLONKish, lookups) |
| Circom `2.2.2` | rapidsnark v0.0.8, and snarkjs 0.7.6 in Node | snarkjs 0.7.6 | R1CS, Groth16 on BN254 |

## Workloads

Every workload is implemented in each system with the same public/private split and identical inputs (`inputs/*.json`, generated by `scripts/gen-inputs.mjs`).

| Workload | What it proves | Noir (UltraHonk gates) | Circom (R1CS constraints, `--O2`) |
|---|---|---:|---:|
| `poseidon_chain` | 100 sequential Poseidon(h, i) hashes end at a public value | 92,256 | 23,700 |
| `merkle20` | leaf membership in a depth-20 Poseidon Merkle tree | 37,262 | 4,840 |
| `sha256_1k` | SHA-256 of a private 1024-byte message equals a public digest | 72,215 | 522,393 |
| `ecdsa_secp256k1` | a secp256k1 ECDSA signature verifies under a public key | 42,180 | not built (see TODO) |
| `cap_check` | 16 private u64 payments: each ≤ per-tx cap, every running total ≤ budget | 3,128 | 4,224 |
| `poseidon2_chain` (variant) | the chain above with Poseidon2, Noir-native | 7,457 | n/a |
| `merkle20_poseidon2` (variant) | the tree above with Poseidon2, Noir-native | 3,044 | n/a |

Poseidon is the circomlib-compatible BN254 instance in both systems (Noir uses `noir-lang/poseidon` `bn254::hash_2`), so the hash outputs match bit for bit: the Noir circuits assert against roots computed with `circomlibjs`. The two *variant* rows use Poseidon2, the hash Barretenberg proves with a dedicated gate. They show what idiomatic Noir costs, and are deliberately kept out of the like-for-like comparison.

`cap_check` is the agent spending-mandate primitive: an agent proves its batch of payments respects a per-transaction cap and a cumulative budget without revealing the amounts.

Gate counts and constraint counts are not the same unit. An UltraHonk gate is a wide PLONKish row with lookups; an R1CS constraint is one rank-1 product. Compare times, not sizes.

## Results

Measured results live in `results/`. Each native run writes `results/<machine>.json` (full samples, machine specs, toolchain, load average) and `results/<machine>.md` (table).

Reference run, MacBook Air M4 (10 cores, 16 GB, fanless), median prove time. Native: 7 reps, host 1-minute load about 9 to 11. Browser: Chrome 154, 10 WASM threads, 3 reps, host load about 11 to 19. Full detail: [`results/SUMMARY.md`](results/SUMMARY.md), [`results/macbook-air-m4-16gb.md`](results/macbook-air-m4-16gb.md), [`results/browser/`](results/browser/).

| Workload | bb native (UltraHonk) | rapidsnark (Groth16) | snarkjs Node (Groth16) | Chrome bb.js (UltraHonk) | Chrome snarkjs (Groth16) |
|---|---:|---:|---:|---:|---:|
| poseidon_chain | 2.00 s | 296 ms | 1.96 s | 4.66 s | 2.23 s |
| merkle20 | 1.02 s | 75 ms | 515 ms | 2.43 s | 523 ms |
| sha256_1k | 1.54 s | 1.46 s | 12.53 s | 3.68 s | 13.91 s |
| ecdsa_secp256k1 | 862 ms | n/a | n/a | 2.15 s | n/a |
| cap_check | 181 ms | 35 ms | 227 ms | 317 ms | 226 ms |
| poseidon2_chain (variant) | 304 ms | n/a | n/a | not run | n/a |
| merkle20_poseidon2 (variant) | 230 ms | n/a | n/a | 479 ms | n/a |

What the numbers say, so far, on one machine:

- On Poseidon-heavy circuits Groth16 wins clearly: circomlib Poseidon is ~240 R1CS constraints per hash, while the same Poseidon costs ~920 UltraHonk gates per hash in Noir.
- Switch Noir to Poseidon2 (its native hash) and the depth-20 Merkle proof drops from 37,262 to 3,044 gates and from 1.02 s to 230 ms natively.
- SHA-256 flips it: 72k UltraHonk gates (lookup tables) vs 522k R1CS constraints. In the browser, bb.js proves it in 3.7 s while snarkjs needs 13.9 s plus a 295 MB key download.
- Groth16 proofs are 256 B and verify in ~10 ms; UltraHonk proofs here are 16,256 B. In bb.js, `verifyProof` also rebuilds the verification key, so browser verify shows 0.07 to 1.5 s.
- Native rapidsnark is 6 to 9x faster than snarkjs on the same zkey, so "Groth16 speed" depends heavily on which prover you mean.

> **Load caveat.** The reference Mac runs many dev sessions in parallel. Every run records `os.loadavg()` at start, end and before each cell. Treat numbers as real-world laptop numbers, not idle-lab numbers.

## Run the native suite

Prerequisites: Node 20+, `nargo` 1.0.0-beta.19, `bb` matching it (`bbup`), `circom` 2.2.x (`cargo install --git https://github.com/iden3/circom.git --tag v2.2.2 circom`).

```bash
npm install
bash scripts/get-rapidsnark.sh          # native Groth16 prover (prebuilt, iden3)
npm run inputs                          # regenerate identical inputs (optional, committed)
npm run build:noir                      # compile Noir -> artifacts/noir (committed)
bash scripts/build-circom.sh sha256_1k  # only the SHA-256 zkey is not committed (~290 MB)
node scripts/sizes.mjs                  # gate / constraint counts (committed)
npm run bench -- --reps 7               # -> results/<machine>.json + .md
node scripts/summarize.mjs              # -> results/SUMMARY.md (native + browser side by side)
```

Flags: `--reps N`, `--workloads merkle20,cap_check`, `--systems noir-ultrahonk,circom-rapidsnark,circom-snarkjs`, `--machine <id>`, `--merge` (re-run some cells and keep the rest of an existing results file).

What is timed:

- **Witness**: Noir via `noir_js` (ACVM in WASM) in Node; Circom via snarkjs `wtns.calculate` (circom WASM) in Node. In-process, after a warmup.
- **Prove / verify**: `bb prove` / `bb verify` and rapidsnark `prover` / `verifier` as CLI calls (wall clock, includes process start and key/CRS load); snarkjs in-process after a warmup.
- **Peak memory**: max RSS from `/usr/bin/time -l` for CLIs, `getrusage` for Node workers.
- **Proof size**: bytes of `bb`'s `proof` file; 256 B for Groth16 (A, B, C as uncompressed BN254 points).

## Run the browser suite

```bash
cd web
npm install
npm run dev        # http://localhost:5173 (COOP/COEP headers set, so WASM threads work)
npm run build      # static site in web/dist
npm run preview    # serve the production build with the right headers
```

To test on a phone on the same Wi-Fi: `npm run dev -- --host` and open the printed LAN URL. Note that browsers only grant `SharedArrayBuffer` (multithreaded WASM) on secure contexts, so plain `http://<lan-ip>` falls back to single-threaded; use a tunnel with HTTPS (for example `cloudflared tunnel --url http://localhost:5173`) for a fair phone run.

The page:

- detects the device (UA, platform, `hardwareConcurrency`, `deviceMemory` hint, cross-origin isolation),
- runs Noir (noir_js + bb.js UltraHonk) and Circom (snarkjs Groth16) on the same artifacts and inputs as the native runner, with a warmup plus 1/3/5 timed reps,
- shows live progress, a per-workload chart and a full table,
- ranks your device against `results/browser/*.json` and the native runs,
- renders a 1200x675 share card (PNG), post text, and **exports a result JSON** (`provebench/browser@1`).

**Submitting a result**: there is no backend yet. Export the JSON and open a PR adding it to `results/browser/`. The next build bundles it into the leaderboard.

Hosting: any static host works if it sends `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (`web/public/_headers` for Netlify/Cloudflare Pages, `web/vercel.json` for Vercel). The SHA-256 Groth16 key is only served if you built it locally; it is opt-in in the UI because it is a ~290 MB download.

Automation hook: `/?autorun=1&reps=3` runs the default suite on load and exposes the result document as `window.__provebench`.

## Trusted setup

Groth16 keys use the PSE perpetual powers of tau (`ppot_0080`, 2^13 / 2^15 / 2^19) and a bare phase 2 (`snarkjs groth16 setup`, no contribution). That has identical proving cost and is fine for benchmarking, but it is **not a secure setup**. Regenerate with `bash scripts/build-circom.sh [circuit ...]`; the ptau files download on demand into `build/ptau/` (not committed).

## Repository layout

```
circuits/noir/<workload>/        Noir packages (Nargo.toml, src/main.nr, Prover.toml)
circuits/circom/<workload>.circom
inputs/<workload>.json           shared inputs (both systems, native and browser)
artifacts/noir/*.json            compiled ACIR
artifacts/circom/*.{wasm,zkey,vkey.json}
artifacts/circuit-sizes.json
bench/                           native runner + workers
scripts/                         input generation, builds, sizes, rapidsnark fetch
results/                         native results; results/browser/ for browser submissions
web/                             Vite static app (browser suite)
```
